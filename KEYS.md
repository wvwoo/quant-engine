| Symptom | Exception | Owner action |

## 4. How a value is resolved

For the two secrets, exactly two sources are consulted, in this order (`qts_core/secrets.py:11-13`, implemented at `:118-145`):

1. **The process environment** — always wins (`secrets.py:130-133`). An exported-but-**empty** variable counts as
   absent (`:130` tests truthiness, documented at `:121-124`): otherwise a stray `export APCA_API_KEY_ID=` in a
   shell profile would permanently shadow a perfectly good file value, and the resulting error would point at
   the file, which is the one place that was actually correct.
2. **`~/.config/secrets.env`** (or `$QTS_SECRETS_FILE`) — consulted **only** if step 1 found nothing
   (`secrets.py:136`), and **only if the file's mode is exactly `0600`** (`:93-94`). Any other mode is refused
   with `SecretsFileInsecure`, and the refusal carries the fix verbatim: `chmod 600 <path>` (`:95-98`).

Two consequences of that ordering, both deliberate:

- A badly-permissioned file can never block a run whose keys are already in the environment (`secrets.py:134-135`);
  verified by `tests/test_secrets.py:164`.
- The insecure file is **refused, not read with a warning**. A warning printed into a log nobody reads is
  indistinguishable from silence, and this file holds exactly the material an attacker wants (`secrets.py:20-23`).

File format (`secrets.py:100-115`): one `NAME=value` per line; blank lines, `#` comments and lines without `=`
are skipped; a leading `export ` is stripped; one matching pair of wrapping quotes is removed. Every value read
is registered for redaction even if no caller ever asks for it (`:114`), so an accidental dump cannot leak a key
this process never used.

**Values are never exported into `os.environ`** (`secrets.py:25-27`). `run_session.sh` spawns `live.py` as a
fresh subprocess on every step (`run_session.sh:87`, inside the `while :;` loop at `:76`), so exporting would
hand every secret to every child process for the lifetime of the session. `tests/test_secrets.py:321`
(`test_environment_is_left_unmodified`) asserts this.

The 13 operational variables use no such machinery: each is a single `os.environ.get(...)` with an inline
default, or a `${VAR:-default}` in shell. Nothing is layered, nothing is cached across a process boundary.

## 5. What is NOT validated, and why

**Alpaca publishes no key format.** No prefix, no length, no character set, anywhere — verified against
docs.alpaca.markets on 2026-07-30 (`secrets.py:29-35`). Any local claim to "validate an Alpaca key" would be
invented, and an invented rule would eventually reject a valid credential.

`qts_core.secrets.looks_plausible()` (`secrets.py:148-169`) is therefore an explicitly **HEURISTIC structural
check**. It rejects only what cannot be right under *any* format:

| Rejected | Line | Reason string (never contains the value) |
| :--- | :--- | :--- |
| empty / whitespace-only | `:159-160` | "value is empty" |
| embedded whitespace | `:161-162` | "…contains whitespace (a stray newline or a padded paste?)" |
| leading or trailing quote | `:163-164` | "…is wrapped in quote characters — paste it unquoted" |
| non-ASCII or non-printable | `:165-166` | "…contains non-printable or non-ASCII characters" |
| shorter than 8 characters | `:167-168` | "…is only N characters — implausibly short for a key" |

Everything else passes, with the reason string
`"structurally plausible (heuristic only; not a vendor format check)"` (`:169`).

**State the limitation as a limitation, not a feature:** this function separates *"you pasted the value wrong"*
from *"the service rejected your key"*. It **cannot** confirm that a well-formed string is a real credential.
Only a live call can do that. The codebase attributes that job to `qts doctor` (`secrets.py:35`) — see §7: that
command does not exist in this worktree.

Note also that `looks_plausible()` is **not** on the broker path. `AlpacaPaperBroker.__init__` checks only
truthiness (`broker_alpaca.py:140`); a structurally broken but non-empty key is sent to the venue and comes back
as `AlpacaAccountRejected`. The heuristic is a diagnostic helper, not a gate.

Not validated anywhere, by design or by omission:

- `QTS_SECRETS_FILE`, `QTS_DB`, `QTS_BACKTEST_DIR` — path strings, never checked for shape. Absence is
  reported honestly at use time (`connected: false`, `available: false`, `{}`) rather than guessed at.
- `QTS_LIVE_TRADING_OWNER_ACK` — compared for exact equality only (`config.py:313-314`); nothing else about it
  matters, because the gate refuses either way.
- `DB`, `REPORT`, `PY` — no pre-flight existence check in `run_session.sh`; failures surface as a step exit code
  and the loop reports and continues (`:88-92`).
- `INTERVAL`, `WAIT_FOR_OPEN` — no shape check. See their rows: a bad `INTERVAL` aborts *after* one step, and a
  truthy-but-not-`1` `WAIT_FOR_OPEN` silently means off.

## 7. Gaps found while compiling this registry

Four things this registry's own subjects reference but the worktree does not contain or does not do. Listed
because each one is reachable by an owner following an error message.

1. **`KEY_ACQUISITION.md` does not exist.** `secrets.py:54` sets `_ACQUISITION_DOC = "KEY_ACQUISITION.md"` and
   names it in every `SecretMissing` message (`:143`); `broker_alpaca.py:144` ends the
   `AlpacaCredentialsMissing` message with "Steps: KEY_ACQUISITION.md". There is no such file at the repo root.
   An owner who hits the absent-key halt is sent to a document that isn't there.
2. **`qts doctor` does not exist.** `secrets.py:35` assigns the "is this a real credential" job to it, and
   `yfinance_source.py:183` mentions "doctor's re-check". There is no `doctor` module, and `pyproject.toml` has
   no `[project.scripts]` — so the only thing that could confirm a key is live is unimplemented.
3. **`.gitignore:28` (`*secrets*`) ignores the new secrets layer.** `git check-ignore -v` confirms it matches
   both `qts_core/secrets.py` and `tests/test_secrets.py`, and `git status --porcelain --ignored` confirms both
   files are ignored and **untracked**. The pattern was written for `.env`-style files but has no path anchor,
   so it also catches source. A plain `git add` will silently skip the entire secrets module and its 40+ tests;
   committing them needs `git add -f` or a narrowed pattern (e.g. `secrets.env`, `*.secrets`).
4. **`artifacts.py:43`, `DEFAULT_DIR`, snapshots `QTS_BACKTEST_DIR` at import** and is referenced nowhere else
   in `qts_core/` or `tests/`. Inert today; a latent trap for any future caller.

Two clarifications where the code is narrower than it might be described:

- `AlpacaPaperBroker.__init__` does **not** inspect `cfg.broker_backend` — it takes no `cfg` argument at all.
  Its only condition is `if transport is None` (`broker_alpaca.py:132`). The backend gate lives in the caller,
  `live.py:119`. Both conditions must hold for a key to be read, but they are enforced in two different files.
- A malformed `QTS_SESSION_DATE` produces an HTTP 500 on two routes, not a crash — and it also leaks one open
  SQLite connection per failing request, because `store = _store()` precedes `_session_date()` and the
  `try/finally: store.close()` begins after it (`api.py:65-69`, `:159-163`).
